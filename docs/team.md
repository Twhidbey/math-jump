## Play together: Team Boss on two devices** (owner, Nov 14 2026)

Home button `#teamBtn` (the icon row is 6 columns now) → `openTeam` (`#team`: lobby `#tmLobby`, game `#tmPlay`). One device `tmHost` (4-letter code from `TEAM_ABC`, no vowels), the other `tmJoin`. **Backend: the owner's Firebase Realtime Database** `TEAM_DB` (project math-ninja-team), plain `fetch` + `EventSource` on `rooms/<CODE>.json`, no library. Room = `{ t, boss (world index), max (TEAM_HP 20), r (round), p: { h: { i, hits }, j: { i, hits } } }`; **each device only writes its own `hits`**, boss health = `max` − both, so nothing collides. Only the player's picture id is sent, never a name (the repo and DB address are public). `tmListen` applies `put` / `patch` events to `team.room` → `tmSync` (room gone = partner left; both ninjas in = `tmStart`; `r` changed = new round) → `tmDraw` (health bar, counts, a shuriken `tmStar` per new hit from each side). Questions: `genFor(curSkill())` on each device (each kid's own math), `tmPick` (`noteFact`; miss shows the answer, 1.7 s), keys 1–3 / , . / via `teamKey`. `tmWin`: 10 + own hits gems to `prog.bank`, win card, **Play again** from either screen (`tmAgain` bumps `r`, new boss). Leaving (`tmClose(true)`) deletes the room; `tmHost` also deletes rooms older than 3 h. Testing needs the network: launch Chromium with `proxy: { server: process.env.HTTPS_PROXY }` and `ignoreHTTPSErrors`, two contexts; this session's cloud environment `math-jump` allows the DB host. **DB rules**: started in test mode (open, expires ~Dec 14 2026). **To do before then:** give the owner rules to paste in the Firebase console (rooms only, 4-letter codes, small fields; every field the game writes must be allowed: see the room fields in this file). **Team run** (owner, Nov 14 2026: "can we team play one of the worlds?"): the host picks **Fight a boss** or **Run this level** (`#tmModeBox`, `#tmLvl` = the host's opened levels; room `mode: 'run'`, `lvl`). Both devices `tmRunStart` → `startStage(lvl)` with their own math; levels are laid out per kid (stones vs bridges, walls), so the partner is shown on a **HUD track**, not in the level: `tmRunTick` (from `update`, every 15 frames, see below) sends `p/<who>` `{ x (percent), g (gates solved) }`, `tmRunHud` (from `drawHUD`) draws the line with both pictures and "Partner: n gates", `tmRunSync` toasts "Your partner opened a gate!" / "is home!". `finishLevel` calls `tmRunDone` (`done: true`) and adds `#tmRunBox` to the end card (`tmRunBoxHTML` / `tmRunBox`, refreshed live): waiting for the partner, then the **team chest** = a gem per gate the two opened (`team.paid` once) and **Next level together ▶** (bumps `r` + `lvl`; both devices restart). `startStage` of another level or `toMenu` ends the run (`tmClose(true)`; the other kid gets a toast and keeps playing alone); the update-reload is skipped while in a team run. **The partner's ninja in the level** (owner: "can you see each other?"): `tmRunTick` now runs every 15 frames (one request in flight at a time, `team.busy`) and also sends `px, py, f (face), a (in the air), sig, su, ba` (suit / headband ids); `drawTeamGhost` (first in the `render` line that draws the player) eases a 60%-alpha ninja (`tmGhostSpr`, baked per suit + band; the diver in Sunken Ship) toward the partner's spot with their picture over its head. `tmSig(L)` = the layout in numbers: same signature → exact `px, py`; different (other math, other Easy) → the same percent of my level, on my ground (highest floor from row `GR` up; in the sea at swimming depth). It touches nothing. Hidden when the partner is home or I am in a room. **The Shadow Twins** (owner, Nov 15 2026: "team villains", then "they hop in and harass several times in the level and then a big battle at the end ... math for a couple of questions and then a Mario-style battle with just attacking (for fun)"; only in team runs, every run; an earlier version with one shared 20-point bar and a constant chase was replaced).
