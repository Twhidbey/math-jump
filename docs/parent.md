# Math Ninja notes: the parent page

Part of the code notes; `CLAUDE.md` has the index. Search `index.html` / `parent.html` for the names in backticks.

## What it is (owner, Nov 2026)

`parent.html` is a separate page (its own link, not linked from the game): each kid's play time (today, last 7 days, playing now), a daily time limit per kid, their math level and plain suggestions. Owner chose: when time runs out the kid finishes the level they're in, then "Time's up for today!"; a 4-digit parent PIN.

## Data (the team database, `TEAM_DB`)

`families/<8-char code>`: `made` (server time), `kids/<kidId>` (the game's report), `limits/<kidId>` (`{on, mins, extra: {day, mins}}`, written by the parent page). Only numbers, the grade, the player's picture (a small PNG data URL) and plain-text facts/suggestions are sent: **never a name**. The parent names each kid on their own phone (`mathninja-parent` in localStorage: `fam`, `pin`, `names`). The PIN is only on that phone; "Forgot the PIN?" asks for the family code. The database rules allow `families/$fam` (8 letters/numbers) next to `rooms/$code` and deny everything else; the owner pasted them on Nov 20 2026 (text in `HANDOFF.md`). Any new path the game writes needs a rules change first.

## In the game

At the end of the script, above `checkUpdate`: `FAM_KEY` (`mathninja-family`, the device's family code), `famKid` (`prog.kidId`, random, per player), the 1-second timer (counts `prog.time[YYYY-MM-DD]` while the page is visible and the kid is in a level/race or touched something in the last 2 minutes; keeps 14 days), `famPush` (every 60 s, after each level, when the app goes to the background), `famPull` (the limit, every 60 s and when the app comes back), `famLeft`, `famStop` (at the top of `startStage`, `startRace`, `tmHost`, `tmJoin`), `famTimeUp` (the card: Check again / Switch player), `famMath` (grade from `trackPlan`, belt, each grade track's %, current skill, weak facts, right-but-slow facts), `famSuggest` (up to 4 sentences). "5 minutes left today!" and "Time's up! Finish this level." float over Kai. Settings > `famBtn` "Parent page" links the device (type the family code; checked against `made`); unlinking needs the code too. Nothing happens on a device that isn't linked.

## Honest limits

It only sees time inside Math Ninja (not the whole device; that's Apple Screen Time). Clearing the browser's data or using another browser gets around it. Anyone who knows a family code could read or change that family's data (no names in it).

## Stop after this level (owner, Nov 20 2026)

Parent page: a red **Stop after this level** button on each kid (and **Stop everyone after this level** at the top when there's more than one) writes `stop: <today>` into `limits/<kidId>`; **Let them play** removes it. In the game `famStopped()` makes `famLeft()` 0 for today only (it clears by itself the next day): the kid finishes the level they're in ("Last level! Finish this one."), then the card says "Time to stop! Great work today, Sam! See you next time." (Check again / Switch player). The game asks for the limit every 20 s.

## Tap for details (owner, Nov 20 2026: "summary, but I can dive in")

The game also sends `families/<code>/detail/<kidId>` after each level, when linking and at start-up (`famDetail` / `famPushDetail`, about 20 KB): each grade track's skills (passed / now / later, gold of n), every fact of them (status, right-and-fast count, wrong count, slow, days since last seen), Think skills' last 10 tries, 14 days of play time, `prog.plog` (each level played: time, name, skill, right, wrong, medal or ran out of hearts; `famLog` in `finishLevel` and `gameOver`; kept 14 days, from Nov 20 2026 on), levels won with medals and golden gems, badges, the closest badges, friends, gems, gates. The parent page shows it in `<details>` sections (`dt`): tap a kind of math (skills + a coloured fact grid; tap a fact for its numbers, `factInfo`), the week chart (14 days with the levels played), the tricky / slow chips, and Progress. Open sections survive the 20-second refresh (`openSet` in sessionStorage).

## Parent PIN on the kids' devices (owner, Nov 20 2026: switching player got around the time limit)

On a linked device, switching to another player, adding one, or opening Edit (change / delete / move) asks for the parent PIN (`famAsk`, from the Players screen in `showPlayers`). The parent page saves `sha256('mn:<code>:<pin>')` at `families/<code>/pin` (`sendPin`, once per family, again after a new PIN); the game caches it in `mathninja-family-pin` (refreshed by `famPull`). Before the parent page has sent a PIN, the family code works instead. The prompt is asked first (still inside the tap, for iPhone) and checked after. Unlinked devices are unchanged.

## Switching families (owner, Nov 20 2026, after losing a code)

Parent page: **Switch family** (bottom) opens `setup()` in switching mode: the families used on this phone before (`st.fams`, up to 8, tap to go back), another code, or a new empty family (asks first). The PIN stays the same and is sent to the new family (`sendPin`). In the game, Settings > Parent page on a linked device asks for the parent PIN or the family code (`famLink`), then offers **Link to another family** (`famLinkNew`: the same kid id moves over, its limit is cleared until the new family sets one) or **Unlink**. Lost code: the Firebase console's Data tab shows `families/<code>` (the owner can see it; the rules hide the list from everyone else).

## Cloud saves (owner, Nov 22 2026: "so it isn't only stored on the device"; chose: no names online)

On a linked device every player's whole save is backed up to `families/<code>/saves/<kidId>` = `{ meta: {at, icon, grade, pts}, data: <prog as JSON text> }` (text, because Firebase keys can't hold `/` and drop empty objects). Names never go up: a restored player types their name again. `prog.syncAt` = the `at` this device last wrote or read; `prog.syncSig` = `famSig` (a hash of the save without `time`, `limit`, `syncAt`, `syncSig`). `famSync` (start-up, every 60 s, coming back to the app, after each level, switching player; never while a level, race or pause is running): reads `meta`; if `at` ≠ `syncAt` another device saved, so it takes the cloud copy, or `famMerge`s when this device changed too (the save with more `stats.right` leads; best scores max, badges / golden / friends / gear / moves added in, facts by latest `last` with days joined, stats max, play time per day max, level log joined); then `famBackup` sends the save if its hash changed. Going to the background: `famBackup(true)` (keepalive under 60 KB). `famBackupOthers` sends the other players on the device once (`famUsed`: never-played players are skipped). Players screen: **☁️ Saved players** (linked devices, PIN) → `famRestoreList` (pictures, grade, belt, "saved 2 days ago"; players already on the device are hidden) → `famRestore` (asks the name, adds the player). Linking a device offers "Get a saved player" when the family has players that aren't on it. The parent page shows "Backed up 5 min ago" (`kids/<kidId>/backup`); Remove player also deletes `saves` and `detail`. `famLinked()` is safe before `famCode` exists (the player screen can open at start-up).

## Time across devices (owner, Nov 22 2026)

The daily limit counts every device a kid plays on. Each device keeps its own count in `prog.time` (never merged by cloud saves; a restored player starts at zero) and `famPush` sends it to `families/<code>/time/<kidId>/<device>` (`famDev`, `mathninja-device` in localStorage). `famPull` adds up the other devices into `famOther`; `famSecs` = this device + the others, so the limit, the report and the parent page's chart all count the total. Remove player also deletes `time/<kidId>`.

## One more level, and +1 min (owner, Nov 24 2026)

- **One more level:** on the parent page, a kid who is stopped or out of time gets a **One more level** button. It writes `more: {day, n: <time>}` into `limits/<kidId>`: a one-use pass. In the game `famMore()` is true while today's pass is unused; then `famStop()` lets a level, race or team game start although `famLeft()` is 0 (it notes `prog.moreAt = {n, t}`), and the time-up card closes by itself with a "One more level!" toast (the 1-second timer; the limit is fetched every 20 s, or at once with Check again). **Finishing** a level or a race uses the pass up (`famMoreDone` in `finishLevel` / `finishRace` sets `prog.moreUsed = n`); running out of hearts or going back to the menu does not, so the kid really gets to finish one; the pass also ends 20 minutes after its first start. The game sends `more: prog.moreUsed` in its report (`kids/<kidId>`), so the page shows "One more level: allowed" until then, and afterwards the button again with "They played their one more level". A team game started on the pass is not counted as finishing (only levels and races are).
- **+1 min:** next to "+15 min today" (only when the daily limit is on); both add to `extra.mins` for today. It does nothing for a kid stopped with "Stop after this level" (use Let them play or One more level).
- Checked with a pretend database (Playwright `page.route`): stopped → card; pass → card closes; start, leave, start again; finish → used, next level blocked; a second pass works; the page's three states and the +1 / +15 sums. Not checked against the real database or on a phone.

## Extra practice of one kind of math (owner, Nov 24 2026: a 2nd grader needed his times tables but kept getting fractions and two-digit take-away)

Parent page, under each kid's Math: **Extra practice** chips (Off, Times, then that kid's own grade tracks). The pick is saved as `focus: '<track name>'` in `limits/<kidId>` (so it reaches the game with the time limit, within about 20 s; it applies from the next level started). In the game `planStage` uses `focusState(plan, name)` as every world's "home" kind while it is set: the first level of each world is only that kind, and it gets 60% of the questions in levels 2, 3 and the boss (it was 40% for the world's own kind). The kid keeps moving up inside the track as skills are passed; when the grade's track is finished (or the grade has none) the next grade's track of the same name carries on (2nd grade's Times is 2, 5, 10; then 3rd grade's 3, 4, mixed, 6...). Auto mode only (`prog.auto`): a kid whose math level was set by hand in Settings > Grown-ups > Math level is not affected. Measured for a new 2nd grader: Times questions go from about 19% of all levels to about 70%. The Daily Dojo and reviews are unchanged. Per table instead: Badge Book > a times-table tile > Practice / Pick a level.

The Extra practice row is on every kid's card (each grade shows its own kinds: a 3rd grader gets Times, Divide, Big adding, Big take-away, Fractions, Think). When it can't apply (the report says `auto: false`, or no grade is set) the card says so and how to fix it. One kind at a time; the owner asked (Nov 24) about other kinds of emphasis: offered two kinds at once, tricky facts, and a strength setting; nothing chosen yet.

**Low and high times tables (owner, Nov 24 2026):** two more Extra practice chips, `focus: 'Times low'` (2, 5, 10, 3, 4, then mixed 2-5) and `'Times high'` (6, 7, 8, 9, then mixed 6-9), for any grade (`FOCUS_SETS` in the game; `focusName` gives the chip labels on the page). One table at a time in that order; when every table of the half is learned it stays on that half's mixed skill for as long as the chip is on. Simulated for a 2nd and a 3rd grader: the first level of a world is all that table, about 76% of all questions are times tables, and once the 6s are learned the next level uses the 7s.
